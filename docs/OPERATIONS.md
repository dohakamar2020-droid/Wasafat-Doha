# تشغيل وصفات قمر على Vercel

## متغيرات التشغيل

| المتغير                 | مطلوب لـ                              | ملاحظة                                                    |
| ----------------------- | ------------------------------------- | --------------------------------------------------------- |
| `DATABASE_URL`          | الحسابات والإدارة والبلاغات والمزامنة | رابط Neon PostgreSQL حقيقي؛ ليس localhost                 |
| `DATABASE_URL_POOLED`   | اختياري                               | لو موجود يستخدم بدل الرابط الأول في الطلبات               |
| `AUTH_SECRET`           | جلسات الحسابات                        | سر عشوائي لا يقل عن 32 حرفًا؛ لا تضعه في Git              |
| `NEXT_PUBLIC_SITE_URL`  | الفهرسة والمشاركة                     | `https://wasafat-doha-woad.vercel.app` أو الدومين النهائي |
| `BLOB_READ_WRITE_TOKEN` | صور تجارب الحساب                      | مخزن Vercel Blob **Private**؛ الصور لا تنشر علنًا         |
| `YOUTUBE_API_KEY`       | تحديث الإحصائيات وحالة التضمين        | مفتاح API رسمي؛ بدونه تبقى أرقام الرصد السابقة            |

بدون قاعدة بيانات، المكتبة الأولية متاحة ووضع الضيف يعمل. الحسابات واستقبال البلاغات تعرض عدم الإتاحة ولا تدعي حفظًا سحابيًا. عند وجود قاعدة غير متاحة لا يستبدلها الموقع بصمت بنسخة قديمة من المحتوى.

## الإعداد الأول

1. استخدم Node 22 و`npm ci`.
2. ضع القيم الحقيقية في `.env.local` للتشغيل المحلي، وفي بيئة Vercel المناسبة. لا تنس ربطها بـProduction/Preview حسب المطلوب.
3. طبّق `npm run db:migrate` ثم `npm run db:seed` مرة للإعداد الأول. أوامر الترحيل ليست جزءًا تلقائيًا من build.
4. أنشئ حساب المالك من الموقع، ثم على بيئة موثوقة بنفس قاعدة البيانات: `npm run admin:grant -- owner@example.com`. لا تُمنح صلاحية الأدمن من اسم البريد وحده.
5. شغّل `npm run check` و`npm run build`، ثم انشر النسخة المختبرة.
6. تحقق من `/api/health/db`: `connected: true` و`accounts: true`، ثم جرّب حفظًا على جهازين، وبلاغًا يصل للإدارة، ونشر وصفة وأرشفتها.

أداة seed تملأ الدفعة الأولى وتحافظ على محتوى الوصفات الذي حرره الأدمن. لا تستخدم `db:push` بدل الترحيلات على قاعدة إنتاج بها بيانات.

## إدارة المحتوى

- إضافة رابط تتطلب الشيف الحقيقي وشهر النشر الأصلي. لا يجري استنتاج صاحب الفيديو من شيف افتراضي.
- رابط جديد يبدأ كـ«وارد». افتح التحرير، أكمل السبب والتصنيف والمكونات، عاين، ثم احفظ كـ«منشور».
- تفعيل المقادير والخطوات يتطلب الحصص والأدوات والمجموعات والخطوات ونقاط النجاح والأخطاء وتوثيق المراجعة.
- وقت الطبخ الكامل اختياري ويجب توثيقه من المصدر. لا تستعمل مدة الشورت أو مجموع مدد بعض الخطوات كتوقيت كامل.
- اربط مكونات الخطوة بصيغة `اسم المجموعة:اسم المكوّن`، خصوصًا عند تكرار المكون عبر طبقات مختلفة.
- عند تعارض نسخة المحرر أعد تحميل أحدث محتوى؛ لا تعاود الحفظ برقم نسخة مخمّن.
- تحديث YouTube يحدث أرقام المشاهدات وتاريخ الرصد وحالة التضمين، ثم يبطل كاش المكتبة.

## الحفظ والخصوصية

الحفظ السحابي يستخدم رقم مراجعة. إذا تعارض جهازان، تعرض الواجهة اختيار نسخة الحساب أو التغييرات الحالية. الدمج مع الضيف صريح ولا يحدث تلقائيًا عند تسجيل الدخول.

صور الضيف محلية؛ دمج سجلها لا يرفع ملفات الصور تلقائيًا إلى Blob. صور الحساب تمر عبر API خاصة بالجلسة. مفاتيح Blob وYouTube لا تصل للعميل.

لو طلبت صفحة خاصة أثناء انقطاع الاتصال، لا تُعرض نسخة كاش من حساب سابق. واجهة عدم الاتصال تعرض بيانات الضيف المحلية فقط. في حالة تحديث Service Worker، تُحذف كاشات إصدارات التطبيق القديمة المعرّفة فقط.

## أوامر التطوير

`npm run dev` يستخدم المنفذ 3000، ويدعم تمرير `-- --port 4173` أو `-- --host 0.0.0.0` للمعاينات. `npm test` يشغّل اختبارات Postgres في الذاكرة، دون الحاجة لأي مفاتيح إنتاج.


## استعادة كلمة السر (أكتوبر 2026)

- الصفحات: `/forgot` (طلب رابط) و`/reset?token=…` (تعيين كلمة جديدة)، والرابط ظاهر في صفحة الدخول.
- التوكن عشوائي 64 خانة، بيتخزن **هاشه بس** في جدول `password_resets` (ميجريشن `0002_password_resets`)، صالح ساعة، استخدام واحد.
- الإرسال الفعلي للإيميل بيحتاج مزوّد بريد: حط `RESEND_API_KEY` في Vercel — نقطة الإرسال جاهزة في `app/api/auth/forgot/route.ts` (حاليًا بتسجل بس). من غير مزوّد، الرد بيبقى عام ولا يكشف إن كان الإيميل مسجلًا.
- للتجربة المحلية بس: `PASSWORD_RESET_RETURN_LINK=1` بيرجّع رابط الاستعادة في رد الـ API (ما تفعّلوش في الإنتاج من غير مزوّد بريد).
